ChatGPTデータ分析業務効率化

Data agent登場｜ChatGPTで分析

記事の概要

売上が下がった理由を知りたいのに、集計やレポート作成を待っていませんか。ChatGPT Data agentの接続先、権限、始め方を整理し、小さな分析を安全に試すところまでを解説します。

情報確認日：2026年9月11日。OpenAIの公式発表・公式ヘルプと、MIRAINAの運用提案を分けて紹介します。

1. ChatGPT Data agentが発表

OpenAIは2026年9月10日、ChatGPT Workで利用する新しいData agentを発表しました。会社のデータに接続し、「なぜ売上が落ちたか」「どの費用が増えたか」といった質問を会話で調査し、結果を共有できるインタラクティブなダッシュボードへまとめる機能です。SQLや専用の分析ツールを覚えずに、質問から分析を始められる点が発表の中心です。

単にグラフを描くだけではありません。結果を見て追加質問をし、根拠を確認し、次の対応案を整理できます。対応する接続ツールでは、承認後にSlackやメールで関係者へ共有したり、次のアクションへつなげたりすることも想定されています。出典：OpenAI公式発表。

OpenAIによると、社内ではプロダクトチームのほぼ全員と、GTM組織の3分の2超がデータエージェントを利用しています。アルファ版を利用したNTT DATAでは、特に営業・コーポレート部門の非エンジニアが自然言語でダッシュボードを作成・更新できたと紹介されています。これはOpenAIと参加企業による事例であり、すべての企業で同じ成果が出ることを保証する数値ではありません。

2. データ接続と権限の仕組み

Data agentは、Amazon Redshift、Google BigQuery、ClickHouse、Databricks、MongoDB、Snowflakeなどの承認済みデータソースを扱えます。Google DriveやSharePointのファイルも、必要な接続が用意されている場合に分析へ加えられます。さらにPower BI、Tableau、Sigma、ThoughtSpotなど既存のBIツールと連携し、普段の環境でダッシュボードを作る構成も示されています。

層役割確認点
データソース売上・顧客・業務データを提供接続アカウントと対象範囲
意味定義指標名、計算式、データ同士の関係を説明正式な定義と更新担当
Data agent質問、比較、原因調査を会話で進める根拠・期間・絞り込み条件
ダッシュボード結果を可視化し、共有・更新する共有先と含まれるデータ

重要なのは、接続しただけで権限が増えるわけではないことです。公式ヘルプでは、テーブル・行・列の制限を含む接続アカウントの既存権限がクエリにも適用されると説明しています。管理者はDataプラグインとデータソース側のアプリを別々に設定し、利用できる役割やグループを決めます。

3. 表計算AIとの違い

既存のChatGPTでGoogleスプレッドシートを直接編集する方法は、一つの表を作る・更新する操作が中心でした。Data agentは複数のデータ基盤や文書、BIツールを横断し、会社で決めた指標の意味を参照しながら、原因調査と共有用の成果物まで進める点が異なります。

そのため、導入の難所も「きれいなグラフを出せるか」だけではありません。例えば「売上」が受注額なのか入金額なのか、返品を除くのかによって答えは変わります。OpenAIのヘルプは、データウェアハウス、正式な定義やクエリを持つセマンティックレイヤー、共有に使うChatGPT Sitesを少なくとも用意することを強く推奨し、BIツールは任意としています。

MIRAINAの見解：中小企業が最初に整えるべきものは、大規模なデータ基盤より「会議で使う数字の定義表」です。売上、商談数、問い合わせ数など3〜5指標について、計算方法、参照元、更新時刻、責任者を一枚にまとめると、AIの結果と既存レポートを照合しやすくなります。

4. 小さく始める5ステップ

公式ヘルプでは、ChatGPTのプラグイン一覧からDataを選び、必要なデータソースとの接続を完了した後、@Dataを付けて業務上の質問を始める手順が案内されています。実際に利用できるかは、ChatGPT WorkまたはCodexのアカウント・ワークスペースでDataプラグインが許可されていることが前提です。発表ページには一律の追加料金が明記されていないため、契約条件は管理者またはOpenAIへ確認してください。

  1. 一つの判断を決める。「先週の問い合わせ減少を確認する」のように範囲を絞る。
  2. 管理者がDataと対象データソースを許可し、利用者の役割を設定する。
  3. 指標の定義、期間、比較対象、除外条件を確認する。
  4. @Dataへ質問し、使用した根拠と条件も表示させる。
  5. 既存レポートと照合し、差分を説明できてからダッシュボードを共有する。

最初の依頼では、質問だけでなく、データの範囲と検証方法まで書きます。次はMIRAINAが作成した練習用の例です。実際のデータソース名と社内用語に合わせて変更してください。

@Data 先週の問い合わせ件数が、その前の4週間平均から変化した理由を調べてください。正式な「問い合わせ件数」の定義を使い、チャネル別に比較してください。参照したデータソース、期間、フィルター、除外条件を示し、確認できない原因は推測と明記してください。既存の週次レポートとの差分も確認してください。

5. 共有前に確認する4項目

AIの分析は、自然な説明や見やすいグラフになっていても、入力条件が違えば判断を誤ります。OpenAIの公式ヘルプも、結果を利用する前にデータソース・期間・フィルター・指標定義を確認し、既存レポートと異なる場合は条件を比較するよう案内しています。詳しい手順はDataプラグインの公式ヘルプで確認できます。

  • データソース：正式な表・文書を参照し、古いコピーを混ぜていないか。
  • 期間：タイムゾーン、締め時刻、未確定の当日データをそろえたか。
  • フィルター：地域、商品、解約、返品などの除外条件が比較対象と同じか。
  • 指標定義：同じ名前の指標に複数の計算方法がないか。

ChatGPT Sitesで公開する場合は、分析に使ったデータが公開先のサイトへコピーされる点にも注意が必要です。共有相手を選ぶ前に、元データの権限だけでなく、公開物に含まれる明細や個人情報を確認します。Slackやメールへの送信、接続ツールでの操作も、宛先と内容を人が確認してから承認しましょう。

効果測定は、ダッシュボードの本数ではなく「質問から判断までの時間」「既存レポートとの差分件数」「人が修正した回数」で行うと運用改善につながります。KPIの考え方はAI導入ROIを測る4指標も参考にしてください。データ整理から導入範囲を決めたい場合は、MIRAINAの生成AI活用支援でご相談いただけます。

6. まとめ

ChatGPT Data agentは、会社のデータと意味定義を使い、会話から原因調査、ダッシュボード、次の行動までつなげる新しい選択肢です。一方、接続しただけで正しい分析が完成するわけではありません。まず一つの指標と一つの判断に絞り、データソース、期間、フィルター、定義を既存レポートと照合しましょう。数字の意味と共有範囲を人が管理できれば、分析待ちを減らしながら安全に活用範囲を広げられます。
