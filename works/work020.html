2026.08.23 公開 自社開発 / 事業システム

【自社事例】資格試験・教材販売システムを2週間で自社構築し、
初期費用40万円と販売手数料20%を削減。

事例概要

教材販売から受験までを一貫して行える資格試験プラットフォームを、MIRAINAが自社開発した事例です。当初は既存の資格試験システムの導入を検討していましたが、初期費用約40万円に加えて売上の約20%が販売手数料として発生することが判明。Claude CodeとCodexを併用しながら2週間でシステムを構築し、自社開発へ切り替えました。結果として初期費用と継続的な販売手数料の双方を削減しただけでなく、既存システムには存在しなかったカスタム機能まで実装。一定のAI・ITリテラシーを持つことで、事業システムそのものを自社内で構築できることを示す事例です。

DATA

対象業務について

項目 内容
対象 MIRAINA（自社事例）
対象システム 資格試験プラットフォーム（教材販売〜受験まで）
開発期間 約2週間
使用ツール Claude Code / Codex を併用

資格試験システムは、教材の販売、受験者の管理、試験の実施、採点、合否判定、証明書の発行といった機能群を必要とします。一般的には専用のSaaSを契約する領域であり、自社開発の対象として検討されることは多くありません。

BEFORE

初期費用40万円と、
売上の20%が永続的に出ていく構造。

資格試験の実施にあたり、当初は既存の資格試験プラットフォームの導入を前提に検討を進めていました。調査の結果、判明した条件は初期費用約40万円、加えて売上の約20%を販売手数料として支払うというものでした。

初期費用の40万円は一度きりの支出ですが、問題は売上の約20%という継続的なコストです。この手数料は事業が成長するほど絶対額が増えるため、売れれば売れるほど負担が重くなります。事業が軌道に乗った後の利益構造を大きく制約する条件でした。

もう一つの懸念が機能面でした。既存システムは汎用的に作られているため、MIRAINAが必要としていた独自の運用に完全には対応できないことが分かっていました。手数料を払い続けたうえで、やりたいことの一部を諦める。この構造に納得できなかったことが、自社開発を検討する直接のきっかけです。

一方で自社開発には、期間とリソースという現実的な制約がありました。専任の開発チームを持たない状態で、事業システムを一から構築するのは従来であれば数ヶ月規模の話になります。

既存システムを導入する場合
  • 初期費用 約40万円
  • 売上の約20%を永続的に支払い
  • 汎用システムのため独自要件に非対応
  • 事業成長とともに手数料負担が増加
→
自社構築した場合
  • 初期費用・販売手数料ともに削減
  • 売上がそのまま事業に残る
  • 独自のカスタム機能を実装
  • 成長しても追加コストが発生しない

図解：既存システム導入と自社構築のコスト構造比較

SOLUTION

Claude CodeとCodexを併用し、
2週間で事業システムを立ち上げた。

自社開発にあたって採用したのが、Claude CodeとCodexを併用する開発体制です。2つのコーディングエージェントを用途に応じて使い分けることで、専任の開発チームを持たない状態でも事業システムの構築を現実的な期間で完了させました。

構築したのは、教材の販売から受験までを一貫して行えるプラットフォームです。教材購入、受験者登録、試験の実施、採点、合否判定、証明書の発行といった機能を実装しています。

さらに、既存システムの調査過程で「あれば運用が楽になるが、汎用システムには存在しない機能」をいくつか特定していたため、それらを最初から自社仕様として組み込みました。既存システムを導入していれば諦めることになっていた要件を、自社開発では制約なく実装できています。

開発期間は約2週間。従来であれば数ヶ月規模の開発対象を、AIコーディングエージェントを活用することで圧縮しました。

RESULT

初期費用40万円と手数料20%を削減し、
機能は既存システム以上に。

削減した初期費用
約40万円
削減した販売手数料
約20%
構築期間
2週間

自社構築により、初期費用約40万円と、今後継続的に発生していたはずの売上約20%の販売手数料を削減しました。手数料は事業が成長するほど絶対額が増える性質のコストであるため、削減効果は事業の成長に比例して拡大していきます。

さらに、既存システムには存在しなかったカスタム機能まで実装できました。コストを下げたうえで機能面でも上回るという結果になっています。

ただし、この事例の本質は単純なコスト削減ではありません。重要なのは、一定のAI・ITリテラシーを持つことで、事業システムそのものを自社内で構築できるという点です。「外部に払うか、自分たちで作るか」という選択肢を持てること自体が、事業判断の自由度を大きく広げます。

販売手数料 売上の約20% 0%
事業成長時の負担 手数料が比例増加 増加なし
機能 汎用仕様の範囲内 カスタム機能を追加実装
仕様変更の自由度 提供元に依存 自社で即時対応

CHANGE

初期費用40万円と、
売上の20%が毎年浮く。

既存システムを導入していれば発生していた初期費用約40万円と、売上の約20%という販売手数料の双方を削減しました。手数料は事業が成長するほど絶対額が増える性質のコストです。年商500万円なら年100万円、年商1,000万円なら年200万円が毎年出ていく計算になるため、削減効果は事業の成長に比例して拡大していきます。

構築期間は約2週間。Claude CodeとCodexを併用したことで、専任の開発チームを持たない状態でも事業システムを現実的な期間で立ち上げられました。しかも既存システムには存在しなかったカスタム機能まで実装しており、コストを下げたうえで機能面でも上回っています。

この経験を経て、システムが必要になったときの初動が変わりました。従来は「どのSaaSを契約するか」から始まっていましたが、現在は自社構築した場合のコストと期間を必ず並べて比較します。特に手数料が売上に連動する課金体系のサービスについては、比較検討が標準の手順になりました。

POINT

コスト削減事例ではなく、
「自社で作れる」ことを示す事例。

POINT 01｜売上連動の手数料構造から脱却
初期費用40万円よりも本質的だったのが、売上の約20%という継続的な手数料。事業成長に比例して負担が増える構造を、自社構築によって断ち切りました。
POINT 02｜Claude CodeとCodexの併用
2つのコーディングエージェントを用途に応じて使い分けることで、専任の開発チームなしに約2週間で事業システムを構築。AI活用の実務的な適用例になっています。
POINT 03｜既存システムにない機能まで実装
汎用システムでは諦めることになっていた独自要件を、自社仕様として最初から組み込み。コストを下げたうえで機能面でも上回る結果になりました。
POINT 04｜示したのは「選択肢を持てること」
単なるコスト削減ではなく、一定のAI・ITリテラシーがあれば事業システムを自社内で構築できるという事実。契約するか作るかを比較できること自体が事業判断の自由度になります。
